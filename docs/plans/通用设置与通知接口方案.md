# 设置-通用：技能更新、成果删除与桌面提醒接口方案

**状态：** Proposed（仅设计，不代表已实现）
**范围：** WebUI 通用设置与会话成果删除策略。
**不包含：** `skills_auto_update` 的登录后执行逻辑、`notifications_enabled` 之外的桌面提醒事件、浏览器或桌面客户端提醒逻辑、推送服务（APNs/FCM）和跨设备账号同步。

## 1. 设计结论（采用方案 A）

方案 A 的原则是“扩展现有接口，不新造平行资源 API”：

1. 扩展现有 `GET/POST /api/settings`，保存三类通用设置；不新增 `/api/settings/general`。
2. 扩展现有 `POST /api/session/delete`，由服务端读取 `session_delete_artifact` 决定是否同步删除成果；不新增 `/api/artifacts/*`。
3. `skills_auto_update` 仅作为通用设置读写；本期不触发任何登录后技能更新任务。
4. `notifications_enabled` 仅作为通用设置读写；本期不定义任何桌面提醒事件、SSE 扩展或客户端提醒行为。

设置的持久化 owner 仍是 `{HERMES_WEBUI_STATE_DIR}/settings.json`；成果的权威清单仍是
`session_manifest.db`。

### 公共 HTTP 约定

- 普通接口沿用 `hermes_session` cookie 认证；写请求由现有 fetch 包装添加 CSRF header。
- 不接受调用方通过 query/body 旁路指定其它用户的 `account`、`profile` 或会话；服务端从已认证会话校验可见范围。
- 方案 A 不新增 integration 路由；若后续修改现有 integration 响应，仍须遵守 `HERMES_INTEGRATION=1`、`j()`/`bad()` 和中文错误文案约定。
- 现有写接口继续使用 `j()`/`bad()` 返回 JSON；4xx/5xx 的可读 `error` 使用中文，未知状态按失败处理。

### 方案 A 的接口总览

| 接口 | 本次变化 | 调用方 |
| --- | --- | --- |
| `GET /api/settings` | 返回新增设置字段，仍是“默认值 + settings.json”合并后的全量配置。 | 设置页、启动初始化。 |
| `POST /api/settings` | 接受新增字段的部分更新，仍原子写入 `settings.json`。 | 设置页开关变更。 |
| `POST /api/session/delete` | 根据 `session_delete_artifact` 配置同步删除或保留成果，并返回删除结果。 | 会话列表/会话菜单。 |

## 2. 通用设置 API

### 3.1 `GET /api/settings`

沿用现有响应，增加以下字段：

```json
{
  "skills_auto_update": false,
  "session_delete_artifact": false,
  "notifications_enabled": false
}
```

字段约定：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `skills_auto_update` | boolean | `false` | 技能自动更新设置值；本期只保存和返回该值，不触发任何更新任务。 |
| `session_delete_artifact` | boolean | `false` | 删除会话时是否同步删除成果；`true` 删除，`false` 保留。 |
| `notifications_enabled` | boolean | `false` | 桌面提醒设置值；本期只保存和返回该值，不绑定任何提醒行为。 |

`skills_auto_update` 不控制登录流程、Hub 查询或技能文件写入。`notifications_enabled` 不控制浏览器权限、任务状态、SSE payload 或客户端通知。本期不增加事件级开关。

用户在设置页修改 `session_delete_artifact` 并保存后，后续删除会话直接遵循该配置；删除会话时不再弹出成果删除确认，也不需要额外请求参数。
浏览器的 `Notification.permission` 是浏览器 owner，不写入 `settings.json`。

### 3.2 `POST /api/settings`

继续使用现有“部分更新、未知字段忽略、响应返回规范化全量设置”的语义：

```bash
curl -sS -X POST http://127.0.0.1:8787/api/settings \
  -H 'Content-Type: application/json' \
  -d '{
    "skills_auto_update": true,
    "session_delete_artifact": true,
    "notifications_enabled": true
  }'
```

这些字段都是现有设置白名单中的扁平 boolean，服务端按现有规则归一化，未知字段忽略。
旧安装无需迁移：已有 `notifications_enabled` 按原值读写。

`POST /api/settings` 返回与 GET 相同的规范化设置对象，并附带现有认证字段（如 `auth_enabled`、`logged_in`）。
请求体不是对象、字段类型不合法或 CSRF 校验失败时分别返回 `400`/`403`；非法字段不能静默改变其它设置。
设置写入失败时返回 `500`，不能返回成功对象。

## 3. 成果删除与会话删除

### 3.1 删除请求

继续使用现有 `POST /api/session/delete`，请求体只保留原有字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `session_id` | string | 必填，沿用现有安全校验。 |

服务端在请求开始时读取一次 `session_delete_artifact`，并将该值作为本次删除操作的唯一决策值：

```text
校验 session_id / 权限
  -> 读取 session_delete_artifact 配置
  -> 读取当前 Manifest 成果清单
  -> true：删除可安全删除的成果文件
  -> false：保留成果文件
  -> 清理会话状态并返回结果
```

```bash
curl -sS -X POST http://127.0.0.1:8787/api/session/delete \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"s_123"}'
```

成功响应沿用现有最小字段，不新增成果清理明细：

```json
{
  "ok": true,
  "state_db_cleanup_failed": false
}
```

### 3.2 安全和事务规则

1. `session_delete_artifact` 缺失、类型非法或读取失败时按 `false` 处理，禁止在不确定时删除文件。
2. 只删除 Manifest 中 `preview=file`、仍存在且位于受信任 workspace root 下的普通文件成果；`preview=skill`、绝对外部引用、目录和 symlink 均保留并计入 `skipped`。
3. `false` 仍删除会话、journal、state.db/Manifest 行，但不 unlink 成果文件；后续文件不会继续显示为该会话成果。
4. 文件逐项删除；任何无法确认的路径按关闭处理。清理明细不进入删除接口响应。
5. 会话文件、state.db、Manifest DB、workspace 文件由各自 owner 清理；删除完成后发布 `session_delete`，不把文件删除状态伪造成会话状态。

## 5. 状态与生命周期不变量

| 状态 | owner | 释放/清理 |
| --- | --- | --- |
| 通用设置 | `settings.json` | 原子写入；未知/非法字段不落盘。 |
| 会话删除策略 | `session_delete_artifact` 配置 | 每次请求开始时读取一次；本次执行过程中不重复读取，避免决策漂移。 |

关键 invariant：删除决策和实际 unlink 使用同一份重新校验后的 Manifest 清单。

## 6. 实施顺序与验证

1. 扩展 settings 默认值、兼容迁移和 `/api/settings` 的扁平 boolean 校验。
2. 为 `/api/session/delete` 增加按设置删除成果的安全语义和逐文件结果。

最小测试矩阵：

- 设置默认关闭、`skills_auto_update` 与 `notifications_enabled` 仅读写、部分更新和未知字段忽略；
- 删除成果 0/1/多文件、配置 true/false、配置缺失或非法时 fail-closed、Manifest 变化、越界/symlink/外部只读文件；

实现阶段若变更现有 integration HTTP 响应字段，需同步更新 `integration/swagger/openapi.json`、`integration/README.md` 和本方案对应的 API 契约文档；本设计阶段不修改 Swagger。
