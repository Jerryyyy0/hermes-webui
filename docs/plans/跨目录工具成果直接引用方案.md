# 跨目录工具成果直接引用方案

- **状态：** Proposed
- **创建日期：** 2026-08-21
- **范围：** Session Manifest 的 file artifacts、持久化、现有 workspace 文件预览
- **前提：** 不移动、复制或软链接工具生成的文件；保持 `GET /api/session/manifest`、SSE
  `manifest_delta` 和 `GET /api/integration/workspace/file?path=...` 的 URL、method、参数和
  字段形状不变。

## 1. 目标与取舍

当当前 turn 内成功完成的工具明确生成或修改一个文件时，该文件即使位于
`session.workspace` 和 `DEFAULT_WORKSPACE` 之外，也应成为 Artifact。文件继续留在原目录；
Manifest 返回其原始绝对路径，点击后由现有 preview URL 读取。

这是**受控的活引用**，不是不可变快照：路径中的文件后续内容变化、被同名替换或被再次生成后，
Artifact 继续预览该路径的最新安全可读版本。只有文件不存在、已不再是普通文件，或不再满足
路径安全策略时，Artifact 才变为 `expired`。

接受这一模型的明确代价：原始绝对路径会出现在 Manifest、SSE、Inspector 和 turn chip 中；
当前 WebUI 认证范围内的任何浏览器只要知道该路径，就可以请求预览，但服务端仍只会读取
数据库中已登记且当前仍安全可读的 Artifact，绝不接受任意绝对路径。

## 2. 当前限制

目前 mutation 工具参数可保留 workspace 外绝对路径，但普通 file preview gate 只接受
`artifact_workspace_root_for_session()` 内的相对路径。`terminal` 的输出解析则更早拒绝
workspace 外路径。即使绕过这些 gate，现有
`/api/integration/workspace/file?path=...` 也会用 `resolve_integration_rel()` 阻止绝对路径。

直接删除这些 containment 检查不可接受：那会把 Agent/浏览器提供的任意路径升级为本机文件
读取能力，并可能暴露状态、凭据或其它会话文件。

## 3. 决策：外部文件的已验证直接引用

对成功工具的 workspace 外候选，以及最后一条真实 assistant message 中的绝对路径候选，结算时建立
一条外部直接引用 Artifact record；它保存原始绝对路径，但不复制内容。该类型不新增数据库字段，而由 integration 的
`is_external_artifact_reference(row)` 根据绝对路径和 `source_tool` 推导：

```text
is_external_artifact_reference(row) =
  path 是绝对路径
  AND (source_tool 属于允许的 mutation/terminal 工具
       OR source_tool == assistant_prose)
  AND source_tool != media
```

```text
当前 turn 结算
  -> 解析成功 tool_complete 的明确输出路径，或最后一条真实 assistant message 的路径
  -> 路径策略、常规文件与受保护目录校验
  -> 用无跟随的 fd 打开并确认是安全的普通文件
  -> store 写入外部直接引用行
  -> Manifest/SSE 返回 {path: "/absolute/output.docx", preview:"file", source_tool}
  -> 既有 /api/integration/workspace/file?path=/absolute/output.docx
  -> 仅匹配已登记外部直接引用且当前安全可读时读取同一 fd
```

workspace 内 Artifact 保持全部现有行为：相对路径、现有 workspace preview gate、实时文件预览
和文件编辑能力均不变。只有符合上述推导条件的外部直接引用走本方案。

## 4. 证据与边界

### 4.1 可以产生跨目录引用的来源

| 来源 | 允许跨目录 | 证据规则 |
| --- | --- | --- |
| `write_file`、`create_file`、`edit_file`、`patch`、`apply_patch`、MCP filesystem mutation | 是 | 当前 turn 成功 completed 事件中的结构化 path 参数或成功 diff 路径 |
| `terminal` | 是 | 仅静态可解析的 `-o`、`--output`、`--print-to-pdf`、单源单目标 `cp`、`md2word.py INPUT OUTPUT` |
| `skill_manage` | 否 | 保持现有 canonical Skill artifact 规则 |
| `MEDIA:` | 不变 | 继续走现有 media 规则，不走直接引用 |
| 最后一条真实 assistant prose | 是（仅绝对路径） | 绝对路径不限制是否位于当前 session workspace；相对路径必须解析并包含于当前 `session.workspace` |

拒绝 tool start、未配对 result、in-progress、失败、取消、非零 exit code、读取工具、搜索/列目录、
terminal stdout、heredoc、变量/命令替换/通配符和 workspace 扫描。除最后一条真实 assistant
message 的受限路径规则外，Artifact 仍以工具成功输出为证据。

### 4.1.1 修改后的 Artifact 资格矩阵与示例

下表是本方案实施后的最终规则。“登记”仍表示只写 Manifest record，不移动、复制或修改源文件；
所有 `file` 行仍需满足普通文件、可预览和第 4.3 节的路径安全校验。

| 来源 | 可作为 Artifact 的条件 | 入库路径表示 | 可登记示例 |
| --- | --- | --- | --- |
| 成功的文件 mutation 工具 | 当前 turn 的 `write_file`、`create_file`、`edit_file`、`patch`、`apply_patch` 或 MCP filesystem mutation 给出结构化输出/成功 diff 路径 | 在会话 workspace 内按现有相对路径；外部保留绝对路径 | `write_file(path="reports/result.docx")` 成功 → `sessions/<sid>/reports/result.docx`；`write_file(path="/Users/wzq/Documents/result.docx")` 成功 → `/Users/wzq/Documents/result.docx` |
| 成功的 `terminal` | 当前 turn 以零退出码完成，且命令中有静态可解析的输出操作数，例如 `-o`、`--output`、`--print-to-pdf`、单源单目标 `cp` 或 `md2word.py INPUT OUTPUT` | 同上 | `python md2word.py draft.md /Users/wzq/Documents/report.docx` 成功 → `/Users/wzq/Documents/report.docx` |
| 最后一条真实 assistant message 的绝对路径 | 正则命中一个带完整边界的绝对路径；文件当前存在。路径可在 session workspace 内，也可在其外 | 在 session workspace 内按既有相对路径；外部原样绝对路径，`source_tool=assistant_prose` | `已生成 /Users/wzq/Documents/report.docx` → `/Users/wzq/Documents/report.docx`；`已生成 /Users/wzq/workspace/sessions/<sid>/reports/report.docx` → workspace 相对路径 |
| 最后一条真实 assistant message 的相对路径或裸文件名 | 只相对当前 `session.workspace` 解析；解析后仍在其中，且文件当前存在 | 既有 workspace 相对路径 | 当前 `session.workspace=/Users/wzq/workspace/sessions/<sid>`，回复 `已生成 reports/report.docx` → `sessions/<sid>/reports/report.docx` |
| `MEDIA:<local-path>` | 符合既有 Media token 规则的本地媒体交付 | 维持既有 media 行和预览机制，不成为本方案的外部直接引用 | `MEDIA:/Users/wzq/Pictures/chart.png` → 既有 session-scoped media Artifact |
| 成功的 Skill 成果 | 符合既有 canonical Skill artifact 规则 | 维持既有 `preview=skill` 表示 | `skill_manage(action="create", ...)` 成功 → 对应 Skill Artifact |

下列内容**不能**仅凭出现路径就登记：用户消息、较早 assistant message、工具开始事件、失败/取消的
工具、`read_file`/`open_file`、搜索命中、目录列表、terminal stdout、普通 URL、`report.pdf.bak` 这类
截断匹配、相对路径 `../report.docx`，以及任何不满足第 4.3 节安全策略的外部文件。

### 4.1.2 `MEDIA:` 保持独立通道

`MEDIA:` 不属于本方案的外部直接引用。只有 assistant 消息中显式出现的
`MEDIA:<local-path>` 才按现有 media 规则作为成果处理；远程 URL、用户消息中的 `MEDIA:`、
工具结果 JSON 的相似字段和普通链接都不产生 media Artifact。

- workspace 内 media 仍规范化为相对路径，并走既有 workspace 文件预览；
- workspace 外本地 media 仍使用既有 session-scoped media preview 授权，不经
  `/api/integration/workspace/file?path=...` 的绝对路径 allowlist；
- media 行的 `source_tool` 固定为 `media`，因此不满足
  `is_external_artifact_reference(row)` 的 mutation/terminal 或 `assistant_prose` 条件；
- `MEDIA:` 不会新建、刷新或扩大外部直接引用的读取授权。

本方案只扩展成功文件工具与受控 terminal 输出的跨目录成果；媒体交付的资格、授权和预览
继续由现有 media 契约维护。

### 4.2 最后一条 assistant message 的正则边界

必须保留“只扫描当前 turn 最后一条真实 assistant message”的限制；不得扫描更早 assistant
消息、`internal_scaffold`、`context_anchor`、压缩 reference 或工具 result。该扫描是可产生
Artifact 的弱证据：绝对路径可创建外部直接引用；相对路径仅能创建当前 session workspace 内的
Artifact。

正则候选必须通过以下边界：

1. **词法边界：** 路径前后只能是字符串起止、空白、引号、反引号、Markdown 分隔符或标点；
   `report.pdf附件`、`report.pdf.bak`、`abc/report.pdfx` 都不得截断匹配为 `report.pdf`。
2. **路径边界：** 绝对路径规范化后无论是否在当前 `session.workspace` 内都可作为候选：位于
   session workspace 内时按既有 workspace 相对路径表示登记，位于其外时按原始绝对路径登记。
   相对路径（含裸文件名）只相对当前 `session.workspace` 解析，且解析结果必须仍包含于该目录；
   `../` 逃逸、歧义解析和其它 workspace 根均跳过。
3. **文件边界：** 必须是存在、可预览、非目录、非 symlink escape、非 `uploads/`、非 cruft 的
   普通文件；session workspace 外候选还必须通过外部受保护路径策略与无跟随 fd 校验。
4. **归属边界：** 只归属当前 `turn_key`；read evidence 仅抑制本 turn 的同 path prose 候选。

因此回复中的“已生成 `/tmp/report.docx`”会作为当前 turn 的 `assistant_prose` 外部引用候选；
只有文件当前存在且通过外部路径策略与无跟随 fd 校验时才登记并可预览。回复中的
“已生成 `../report.docx`”则不会登记，因为相对路径不得逃出当前 session workspace。

### 4.3 外部路径和 fd 安全

登记时和每次预览时都必须满足：

1. 绝对路径经规范化后是常规文件，不是目录、FIFO、socket、设备文件或 symlink；
2. 从可信文件系统根按组件无跟随打开，或采用等效的 fd-anchored open；验证后使用该 fd，不能
   再按 pathname 重新打开；
3. 文件不位于 `.git`、依赖/缓存/构建目录，也不匹配 `.env`、`auth.json`、`config.yaml`、
   `state.db` 等敏感名称；
4. 明确拒绝以下**由运行时状态根展开后的具体目录**（不是拒绝任意名为 `sessions` 或 `memory`
   的项目目录）：

   - 令 `STATE_DIR` 为 `HERMES_WEBUI_STATE_DIR`，未设置时为
     `${HERMES_HOME:-<平台默认 Hermes Home>}/webui`；拒绝
     `STATE_DIR/sessions/`（WebUI session sidecar）和 `STATE_DIR/memories/`。
   - 附件根为 `HERMES_WEBUI_ATTACHMENT_DIR`；未设置时为 `STATE_DIR/attachments/`。两种配置下
     的该目录及其子目录都拒绝。
   - 令 `HERMES_HOME` 为当前 profile 的 Agent 根；拒绝
     `HERMES_HOME/memories/`、`HERMES_HOME/sessions/`、`HERMES_HOME/cron/`、
     `HERMES_HOME/logs/`、`HERMES_HOME/checkpoints/` 和 `HERMES_HOME/backups/`。命名 profile
     还应覆盖 `<基础 Hermes Home>/profiles/<profile>/` 下的同名目录。
   - 拒绝 `~/.ssh/`、`~/.gnupg/`、已定义的系统保护根及前述状态根中的敏感文件名；项目自身例如
     `/Users/wzq/project/sessions/report.docx` 不因目录名 `sessions` 被拒绝。
5. 无法验证路径、fd、大小或资源上限时 fail closed，不写入该 Artifact；
6. 预览时文件不存在、不再是普通文件或不符合路径安全策略，都不返回字节；GET Manifest 投影
   为 `expired`。

“任意输出目录”只放宽输出位置，不放宽读取授权。若需支持当前受保护目录，必须以单独的
管理员 allowlist 和安全评审增加例外。

## 5. 存储模型与生命周期

### 5.1 Store identity

本方案不增加 SQLite 字段，也不需要数据库迁移。外部直接引用行的 `path` 就是规范化后的
原始绝对路径；`workspace_root` 仍保留现有会话 Artifact 根，维持 store identity、
lineage/profile/turn 隔离和唯一键。绝对 `path` 不参与
integration-root 前缀投影。

外部引用继续适用既有读取与预览大小限制。登记和预览时均须在已打开的同一 fd 上确认它是
安全的普通文件；不得先检查 pathname、再按 pathname 重新打开。超出既有预览能力的文件按
现有下载/预览策略处理，不额外复制、缓存或计算内容摘要。

### 5.2 结算、SSE 与 GET

保持现有顺序：

```text
final assistant durable
  -> 校验 stream_turn_key 与 user anchor
  -> 提取当前 turn 工具强证据和最后一条真实 assistant message 的路径候选
  -> workspace 内走原有 gate（assistant 相对路径仅限当前 session workspace）
  -> workspace 外打开 fd、确认安全性后登记引用
  -> 同一 decision upsert workspace 行和外部直接引用行
  -> completed journal event
```

外部行只有在 store upsert 成功后才发送 `manifest_delta`。`GET /api/session/manifest` 是只读的：
它可对已登记路径重新验证当前可读性并投影 `expired`，但不得 backfill、扫描目录、查找相似
路径或重建证据。聊天 chip 在 `done` 后仍以 GET 为权威。

### 5.2.1 绝对路径的入库与预览流程

以下流程适用于 workspace 外候选：成功 mutation/terminal 工具产生的候选，以及最后一条真实
assistant message 中的绝对路径候选；`MEDIA:` 不进入这条链路。assistant message 中的相对路径
只会产生 workspace 内 Artifact，继续走既有相对路径预览。

```text
1. 当前 turn 结算
   成功 completed 事件给出结构化输出路径或受控 terminal 输出操作数；或者最后一条真实 assistant
   message 的正则给出绝对路径。后者的 `source_tool` 记为 `assistant_prose`。

2. 候选规范化与安全确认
   将路径规范化为绝对 path，确认它在 workspace 外、是普通文件、未命中受保护路径策略；
   从无跟随 fd 读取/预览该文件，不允许“检查后按 pathname 重开”。

3. 入库
   `_persist_turn_artifact_paths()` 在同一 turn decision 中调用现有 upsert：
   {path: "/absolute/output.docx", preview: "file", source_tool: "write_file"}
   若来源是 assistant message，则只将 `source_tool` 替换为 `assistant_prose`。workspace 内的绝对
   路径按既有规则转换为相对 `path` 后入库，workspace 外绝对路径原样入库。
   workspace_root 仍取 session 的既有 Artifact 根；不新增列、不保存副本，也不将绝对路径
   转换为 integration-root 相对路径。

   SQLite 中对应 `session_manifest_records` 的一行示例如下（`id` 由数据库自增，时间为实际写入时的
   Unix 时间戳）：

   ```text
   id:             42
   session_id:     "4f8c3d21-2026-4a6f-9b4c-8da7a6f12b90"
   lineage_key:    "4f8c3d21-2026-4a6f-9b4c-8da7a6f12b90"
   profile:        "default"
   workspace_root: "/Users/wzq/workspace"
   turn_key:       "turn_20260823_153012"
   record_kind:    "artifact"
   path:           "/Users/wzq/Documents/monthly-report/2026-08-summary.docx"
   preview:        "file"
   source_tool:    "write_file"
   created_at:     1787460612.123
   updated_at:     1787460612.123
   ```

   这里 `path` 原样保存外部文件的绝对路径；`workspace_root` 不是该文件所在目录，而是现有会话
   Artifact 根，用于既有 lineage/profile/turn 隔离及唯一键
   `(lineage_key, profile, turn_key, record_kind, path, workspace_root)`。因此无需增加
   `storage_kind`、摘要或文件身份字段。

   对应地，workspace 内文件仍按现有规则保存相对路径，示例如下：

   ```text
   id:             43
   session_id:     "4f8c3d21-2026-4a6f-9b4c-8da7a6f12b90"
   lineage_key:    "4f8c3d21-2026-4a6f-9b4c-8da7a6f12b90"
   profile:        "default"
   workspace_root: "/Users/wzq/workspace"
   turn_key:       "turn_20260823_153012"
   record_kind:    "artifact"
   path:           "sessions/4f8c3d21-2026-4a6f-9b4c-8da7a6f12b90/exports/2026-08-summary.docx"
   preview:        "file"
   source_tool:    "write_file"
   created_at:     1787460613.456
   updated_at:     1787460613.456
   ```

   预览时该行的实际文件路径由 `workspace_root + path` 解析，即
   `/Users/wzq/workspace/sessions/4f8c3d21-2026-4a6f-9b4c-8da7a6f12b90/exports/2026-08-summary.docx`，继续走既有相对路径分支。
   两类记录的表结构、唯一键和 `workspace_root` 均相同；只有 `path` 的表示不同：workspace 内为
   相对路径，workspace 外为原始绝对路径。

   上例中 `session.workspace` 本身确实是每个 managed session 独立的
   `/Users/wzq/workspace/sessions/<session-id>`。但当前
   `artifact_workspace_root_for_session()` 对位于默认 workspace 下的 session 返回默认根
   `/Users/wzq/workspace`，所以数据库行的 `workspace_root` 不是 session 子目录，session 隔离由
   相对 `path` 中的 `sessions/<session-id>/` 前缀和现有 lineage/profile/turn 唯一键共同保证。若
   session 显式使用默认根之外的 workspace，则 `workspace_root` 才保存那个 session 自己的外部根，
   `path` 保持相对该根的普通相对路径。

4. GET Manifest / SSE
   记录满足 is_external_artifact_reference(row) 时，Manifest/SSE 原样返回：
   {path: "/absolute/output.docx", preview: "file", source_tool: "write_file"}
   若源文件不存在、不安全或不可读，GET 返回相同 path 并标记 status: "expired"；GET 不写 DB。

5. 点击预览
   static/workspace.js 继续请求既有 URL：
   GET /api/integration/workspace/file?path=/absolute/output.docx
   handler 发现 path 为绝对路径后，不调用普通的 resolve_integration_rel()；它先查找 path 完全
   相等且满足 is_external_artifact_reference(row) 的已登记 record，再按相同路径策略无跟随打开 fd。
   检查通过后从这个 fd 返回字节；失败时用中文错误响应拒绝，不回显额外路径信息。
```

绝对路径只在 Manifest Artifact、SSE 与该只读 preview GET 中有效；它不能用于
`/api/integration/workspace/files` 枚举，也不能传给保存、删除、重命名、上传或 Git mutation
接口。

### 5.3 删除、替换、修改与恢复

- 删除 session/turn record 不删除源文件；只移除引用；
- rebind 只移动 turn 归属，不动源文件；
- 文件删除、改名、不再是普通文件或路径策略拒绝时，GET 返回同一绝对 path + `status: "expired"`；
- 文件内容修改或同名替换后，Artifact 继续预览该绝对路径的当前版本；
- `replace_manifest_turn_records()` 只替换 record，不能依据旧 path 执行任何文件操作；
- 重启、压缩 lineage 和 profile 隔离继续以现有 store identity 处理；
- 不对历史 workspace 外路径做 backfill，因为缺少可信的工具完成证据。

## 6. 保持预览接口不变的改动地图

### 6.0 Fork 集成边界

新增策略、安全打开和已登记外部引用查询放在：

```text
integration/external_tool_artifacts/
```

建议拆分为 `policy.py`、`references.py` 与 `preview.py`。大型上游文件
`api/streaming.py`、`api/gateway_chat.py` 只保留薄调用。`api/session_manifest.py` 虽位于 `api/`，
但也是本 Fork 新增的模块；本次只让它调用 integration helper，不继续加入外部引用的策略或预览
实现。`integration/workspace/handlers.py` 只保留路由分发。实施时同步更新 `integration/README.md` 和
`docs/hermes-external-integration.md`。公开 URL、参数、请求体和响应 schema 不变，因此无需更新
integration OpenAPI；若实施中改变任一 API 契约，必须同时更新 `integration/swagger/openapi.json`。

#### 6.0.1 模块迁移决策

“迁移”指将已有实现的归属收敛到 `integration/`，不是把上游文件复制一份。下表区分本次功能
必须落点与后续独立治理，二者不可混做一个改动。

| 模块 | 当前归属 | 迁移决定 | 本次动作 |
| --- | --- | --- | --- |
| `integration/external_tool_artifacts/` | 不存在 | **本次新增至 integration** | 新建 `policy.py`、`references.py`、`preview.py`；承载全部新增的外部引用策略、安全打开、引用判定与预览授权。 |
| `integration/workspace/handlers.py` | Fork integration | **不迁移** | 保持在 integration；仅增加到 `external_tool_artifacts` 的薄调用，保留现有 URL 和相对路径分支。 |
| `api/session_manifest.py` | Fork-only | **应迁移，但另立改动** | 本次只加薄调用，不增加策略实现；后续迁至 `integration/session_manifest/`，以 `api/session_manifest.py` re-export shim 过渡。 |
| `api/session_manifest_store.py` | Fork-only | **应迁移，但另立改动** | 本次不修改其业务职责；后续迁至 `integration/session_manifest/store.py`，以 `api/session_manifest_store.py` re-export shim 过渡。 |
| `api/session_manifest_repair.py` | Fork-only | **随 store 一起迁移，另立改动** | 迁至 `integration/session_manifest/repair.py`，保留 API shim；它是 store 的直接依赖，不能遗留在 `api/`。 |
| `api/streaming.py`、`api/gateway_chat.py`、`api/routes.py` | 上游 | **不迁移** | 只保留必要 import/单行钩子，不能加入外部路径策略、SQL 或 fd 操作。 |
| `static/workspace.js` | 上游 | **不迁移** | 只增加绝对路径 Artifact 的只读 UI 分支；不得复制出 Fork 版 workspace 页面。 |
| 新增测试 | 不存在 | **本次放 integration** | 外部绝对路径的授权、拒绝和预览 HTTP 用例放 `integration/tests/`；既有 Manifest 回归测试保留原位置。 |

因此，本次真正需要“迁入/新建”的只有 `integration/external_tool_artifacts/` 及其 integration
测试；三个既有 Fork-only Manifest 模块是应治理的历史边界，但不作为本功能的前置迁移。若决定
立即执行它们的迁移，必须拆为独立 PR，先做 shim 再迁调用方，不能与绝对路径预览混合验证。

#### 6.0.2 Fork Manifest 模块的具体迁移逻辑（独立 PR）

该迁移只改变 Python 模块归属，**不得**改变 HTTP URL、Manifest/SSE schema、SQLite 路径/表结构、
行数据、路径投影或 Artifact 判断。迁移目标如下：

```text
integration/session_manifest/
  __init__.py                 # 稳定的 integration 导出面
  manifest.py                 # 由 api/session_manifest.py git mv 而来
  store.py                    # 由 api/session_manifest_store.py git mv 而来
  repair.py                   # 由 api/session_manifest_repair.py git mv 而来

api/session_manifest.py       # 仅兼容 shim
api/session_manifest_store.py # 仅兼容 shim
api/session_manifest_repair.py # 仅兼容 shim
```

1. **先冻结行为基线。** 在迁移前运行现有 Manifest/store/replay/turn-isolation 回归测试，并记录
   `GET /api/session/manifest`、`manifest_delta` 与 `session_manifest.db` 的样本；迁移 PR 不包含
   外部绝对路径、SQLite schema 或前端改动。
2. **整体移动三个 Fork-only 文件。** 使用 `git mv` 将实现移入上述 package；`store.py` 对
   `repair.py` 的 import 改为 package 内相对 import，两个延迟导入 Manifest 的位置改为
   `integration.session_manifest.manifest`。不复制两套实现，不保留会继续执行的旧实现。
3. **用模块别名做 API 兼容。** 每个 `api/*.py` shim 在导入 implementation 后，将
   `sys.modules[__name__]` 指向对应的 integration module；**禁止**只写
   `from … import *`。模块别名保证已有 `from api.session_manifest_store import …`、
   `import api.session_manifest_store as store`，以及测试对 `STATE_DIR`、函数的 monkeypatch 都作用在
   同一个 module object 上。
4. **按调用方类型切换 import。** `integration/workspace/handlers.py`、
   `integration/workspace/hooks.py`、`integration/crons/hooks.py`、integration tests 与
   `scripts/audit_workspace_profiles.py` 改为直接导入 `integration.session_manifest`。上游
   `api/streaming.py`、`api/gateway_chat.py`、`api/routes.py` 暂保持 `api.*` shim import，避免为
   纯改归属而扩大上游 diff；后续触及这些钩子时再逐个换成 integration import。
5. **数据库零迁移。** `DB_FILENAME`、`STATE_DIR / "session_manifest.db"`、
   `session_manifest_records`、所有 index/unique key、历史空 `workspace_root` 的解释及 repair 行为
   原样保留。不得执行数据复制、backfill、`ALTER TABLE`、删除旧 DB 或重新写入记录。
6. **双入口验证后再清理。** 所有回归测试同时覆盖新入口
   `integration.session_manifest.{manifest,store,repair}` 与旧入口 `api.*`；断言二者模块身份和
   `STATE_DIR` monkeypatch 可见性一致。至少完成一个 WebUI streaming turn、一个 Gateway turn、一个
   cron turn、一次 profile 筛选和一次 rebind/repair 的 DB 前后对比。确认一个发布周期内无外部
   `api.*` 依赖后，才能在**另一个**兼容性破坏 PR 中删除三个 shim。

迁移提交顺序固定为：`package + shim` → `integration/script 调用方切换` → `双入口测试与文档`。
任何一步出现 import cycle、模块状态不共享、DB 行数/唯一键变化或 wire payload 差异，都停止迁移并
保留 shim 回滚，不进入外部绝对路径功能实现。

### 6.1 `api/session_manifest.py`

该文件也是本 Fork 新增的 Manifest 领域模块，当前体积和调用面都较大。完整迁移到
`integration/session_manifest/` 应作为后续独立的兼容式重构处理；迁移期间保留
`api/session_manifest.py` 的薄 re-export shim。此次不扩大它的 Fork 业务逻辑，仅通过薄调用接入
`integration/external_tool_artifacts/`。

1. 候选在运行时显式区分 workspace 与外部直接引用，避免绝对路径被误当相对路径；持久化后
   由 `is_external_artifact_reference(row)` 以 `path + source_tool` 重建该判断；
2. terminal 输出解析允许合格外部输出，但保留静态操作数和成功完成门槛；
3. 对外部候选调用 integration 的安全打开与路径策略 helper；失败即跳过；
4. `_rows_to_wire()` 对 live external row 原样返回绝对 `path`，不走 `_file_preview_path()`；
   路径已不可读或不安全时返回相同 path 加 `status: "expired"`；
5. workspace、Skill 与 MEDIA 分支不放宽；assistant prose 仅按第 4.2 节的绝对/相对路径边界
   产生 Artifact，不能扫描其它 message 或从非路径文本推导文件。

### 6.2 `api/streaming.py` 与 `api/gateway_chat.py`

`_persist_turn_artifact_paths()` 是 normal、error/cancel、Gateway 的共同 settlement 边界。
在此处统一登记外部引用，不能只修 browser streaming 或单独 Gateway。SSE 的外部行必须在
路径策略和 DB record 都完成后发送。

### 6.3 `api/session_manifest_store.py`

该文件是本 Fork 新增的 Manifest SQLite 持久化层，而非上游已有模块。它已经被 Manifest、streaming、
routes、workspace 和 cron 等多处调用；完整迁移会同时改动这些调用和大量测试，因此不应与本次
“外部绝对路径引用”功能耦合。

本方案不在该文件新增外部引用逻辑。若后续要收敛 Fork 边界，应另立一次兼容式迁移：将实际实现移至
`integration/session_manifest/store.py`，`api/session_manifest_store.py` 暂保留为薄 re-export shim，
待调用方逐步改为 integration import 后再删除 shim。这样可以降低迁移风险，也不会阻塞本方案。

1. 不增加 SQLite migration；继续无差别保存 `path`、`source_tool` 和 record 的完整副本，不理解
   “外部引用”这一业务概念；
2. `is_external_artifact_reference(row)` 实现在
   `integration/external_tool_artifacts/references.py`，由 Manifest projection 与 preview allowlist
   共用，避免各处依靠字符串猜测；store load 只返回原始行；
3. 保持唯一键、empty decision、lineage/profile/workspace-root 范围不变；
4. 删除和 rebind 只影响数据库，永不 unlink、rename、copy 或修复外部源路径。

### 6.4 `integration/workspace/handlers.py` 与前端

`GET /api/integration/workspace/file?path=...` 保持不变：

1. `path` 为绝对路径时，调用 integration helper 查询是否存在由 `is_external_artifact_reference()`
   判定的已登记外部引用；
2. 仅记录存在、路径策略允许且 fd 验证通过时，以这个已打开的 fd 提供现有 MIME、`no-store`、HTML/PDF sandbox
   行为；否则用中文错误响应拒绝，且不得回显路径；
3. 相对路径继续调用当前 `resolve_integration_rel()`，行为不变；
4. `/api/integration/workspace/files` 不枚举外部引用；workspace save/delete/rename/upload/Git 等
   mutation endpoint 继续拒绝绝对路径；
5. `static/workspace.js` 对绝对 Artifact path 预览设为只读，隐藏编辑/保存操作；下载继续复用同一
   GET URL。

路径可见是本方案的已知 UI 取舍；Inspector/turn chip 显示绝对路径，前端不得再把它转换为
session-relative workspace 路径。

## 7. 测试与验收

| 维度 | 必测场景 |
| --- | --- |
| 来源 | write/create/edit/patch、MCP mutation、terminal `-o`/`cp`/`md2word.py`；read/search/stdout 被拒绝 |
| 位置 | session workspace、DEFAULT_WORKSPACE 同级、外部普通目录、home 外已批准目录、受保护目录 |
| 活链接 | 删除、改名、symlink、受保护路径和不可读文件变为 `expired`；内容修改或同名替换继续预览当前版本 |
| 生命周期 | 成功、失败、取消、SSE 后刷新、Gateway、DB 失败、重启回放、replace/rebind/删除 |
| 隔离 | 多 session、profile、同路径不同 turn、compression lineage；绝对路径不经相对化串读 |
| 路由 | 原 workspace 预览不回归；已登记绝对路径可预览；未登记/过期/受保护绝对路径均拒绝；外部 Artifact 不可编辑 |

基础回归命令：

```bash
./scripts/test.sh \
  tests/test_session_manifest.py \
  tests/test_session_manifest_store.py \
  tests/test_session_manifest_contract.py \
  tests/test_session_manifest_replay.py \
  tests/test_session_manifest_artifact_persistence.py \
  tests/test_artifact_turn_isolation.py \
  -q
```

另需新增 integration HTTP 测试：同一个既有 preview URL 能读取已登记且未变化的外部文件；任意
crafted path、已删除路径、symlink 和受保护文件都不可读取，响应不得泄露源路径；内容变化的已登记路径仍可读取当前版本。

## 8. 非目标

- 不移动、复制、软链接、归档或同步生成文件；
- 不把 Manifest 变成全盘文件索引、执行 journal 或完整文件变更账本；
- 不允许 `MEDIA:`、读取和搜索结果创建任意目录的 Artifact；assistant prose 只允许最后一条真实
  message 中符合第 4.2 节边界的路径，且仍受普通文件、受保护路径和无跟随 fd 校验；
- 不允许凭任意绝对路径直接读取文件；必须有同一 Artifact record 且路径当前仍安全可读；
- 不修改 workspace 内文件预览、编辑、下载或路径语义；
- 不新增 preview endpoint、query 参数、Manifest/SSE 字段或版本；
- 不自动回填历史 workspace 外路径。

## 9. 实施切分与文档同步

1. **安全引用基础**：integration helper、受保护路径策略、fd 校验和单元测试；
2. **Store 迁移**：新列、upsert/replace/load、过期投影与旧库兼容；
3. **统一结算**：normal/Gateway/error/cancel 的外部工具候选登记与 SSE 收口；
4. **现有预览路由**：同一 endpoint 的绝对路径 allowlist 分支、前端只读状态和 HTTP 攻击测试；
5. **故障演练**：并发替换、路径 race、profile/lineage 隔离、重启和 session 删除。

代码实施时同步更新：

- [Session Manifest HTTP/SSE 契约](../api/session-manifest-api.md)：`preview=file` 可返回经验证的
  外部绝对路径，文件变化后以 `expired` 表示；
- [Session Manifest Artifacts 实现](../architecture/session-manifest-artifacts.md)：外部工具输出、
  路径安全、直接引用和过期规则；

  默认根外文件从“不展示”变为“有认可来源证据且路径当前安全可读时直接引用展示”。
