# 压缩摘要上下文锚点修复方案

- **状态：** Implemented locally; pending final verification
- **范围：** Hermes Agent 压缩结果、`state.db` 语义字段，以及 Hermes WebUI 的读取和展示投影。
- **不包含：** 重写历史会话、来源身份迁移、`_turn_key` 冲突治理或改变真实 user 的 provider 请求整形。

## 问题

`ContextCompressor` 会生成 `[CONTEXT COMPACTION — REFERENCE ONLY]` 摘要。它是模型恢复材料，不是用户输入；但当前仅带 `_compressed_summary=True`，可能作为普通 `role=user` 进入 durable transcript。

当压缩器无法在既有 role 边界插入摘要时，还会把摘要文本合并进真实 tail user。此时不能给整条合并结果打 `context_anchor`，否则真实用户请求会从展示和 turn 投影中消失。

## 目标与不变量

1. 压缩摘要在重启后仍可参与模型上下文恢复。
2. 压缩摘要永远不是可见 user 气泡、真实 user turn 或 artifact/manifest 的归属锚点。
3. 真实 tail user 的内容、`_turn_key`、来源身份和 `api_content` 不因摘要分类而被改写或隐藏。
4. provider 可继续获得角色合法的临时上下文；该临时整形不得写回 canonical transcript。
5. 既有会话不迁移、不按摘要文本启发式删除或重写。

## 现有可复用契约

不新增消息类别。复用 Agent 的 `_hermes_message_class="context_anchor"` 与 `_hermes_scaffold_kind`，新增 kind=`compaction_summary`。

该类别已能写入 Agent `state.db`，并被 WebUI 的语义分类、展示过滤和 turn 投影识别。`internal_scaffold` 不适用，因为它会被 Agent 持久化层跳过，重启后摘要会丢失。

## 实施方案

### 1. Agent：为摘要统一写入权威语义

在 `ContextCompressor` 产生摘要时，使用一个**不改写既有 role**的统一 helper 标记
`context_anchor/compaction_summary`。现有 `make_context_anchor()` 固定生成 user role；需要补充接收既有消息并原样保留 `user` 或 `assistant` role 的标记 helper，避免复制字段写入逻辑。

摘要 role 继续沿用压缩器现有的边界决策：没有幸存 user 时必须为 user；其他情况可为 user 或 assistant。只有在当前算法原本会进入 `_merge_summary_into_tail`（两侧均无可安全插入 role）时，目标实现必须将摘要降级为独立的 **user-role** anchor。

这个降级规则不能选 assistant：`repair_message_sequence()` 会在 canonical history 合并相邻 assistant；若 tail 是真实 assistant，摘要与 tail 会被合并，导致真实 tail 继承 `context_anchor` 语义并被隐藏。相邻 user 则由 provider-only 副本处理，不污染 canonical transcript。

`_compressed_summary` 可暂时保留为压缩器内部定位标记，但不得再作为持久化或展示分类的唯一依据。语义判断必须只依赖 `hermes_message_class` 与 `hermes_scaffold_kind`。

### 2. Agent：拆开“摘要合并进 tail”的表示

删除 `ContextCompressor` 中 `_merge_summary_into_tail` 的文本拼接分支：摘要独立写入 `context_anchor/compaction_summary`，并保留 end marker。命中原 merge 条件时，按第 1 节降级为 user-role anchor；其他情况保留既有的摘要 role。真实 tail 按原字节内容、元数据和 `api_content` 写入，不再调用 `drop_stale_api_content()`。

当原有边界算法得出 user-role 摘要且 tail 也是 user 时，canonical transcript 保留相邻两条 user。这不是持久化错误；禁止为了“交替”把两条真实语义不同的记录合成一条。该 anchor 不携带真实 user 的 `_turn_key`、来源身份或 `api_content`。

若 canonical history 因此出现相邻 user，沿用现有 provider-only 合并 helper 生成 API 副本。该 helper 的输出不得进入 `state.db`、sidecar 或 SSE user 事件。

provider-only 合并继续使用现有 `_drop_thinking_only_and_merge_users()` 接缝，不调整
`conversation_loop` 中全局 prompt-cache 顺序。当当前分支已先注入
`cache_control` 时，provider helper 保留这些临时 content block；不重新计算
breakpoint，也不将它们写回 canonical transcript。这是为了把 Fork 补丁限制在
既有 provider 整形接缝，避免改变所有启用缓存的普通请求。

### 3. WebUI：扩展既有类别测试，不扩展展示模型

WebUI 已按 `context_anchor` 过滤控制消息。本次只将 `compaction_summary` 加入 context-anchor kind 的回归参数集，验证 state.db replay、`done.session.messages`、分页和 turn/manifest 投影均不显示或归属该行。

未知 kind 继续按已有保留优先策略处理；旧摘要因缺少权威类别不自动隐藏。历史会话只通过后续只读审计列出候选，不修改原始行。

## 测试计划

每条测试先在未修复实现上失败，再在修复后通过。

| 场景 | 断言 |
| --- | --- |
| 独立 user-role 压缩摘要 | `state.db` 保留 `context_anchor/compaction_summary`；WebUI 不展示该行；模型恢复仍包含摘要 |
| 独立 assistant-role 压缩摘要 | 语义字段保留原 role；展示和 turn 投影仍过滤 |
| head=assistant、tail=user（现有 merge-into-tail 触发条件） | 摘要独立且带 end marker；tail 的内容、`_turn_key`、来源身份、`api_content` 字节级不变；不再调用 tail 合并或 sidecar 删除 |
| head=user、tail=assistant（另一 merge-into-tail 触发条件） | 摘要降级为 user-role anchor；`repair_message_sequence()` 不产生 assistant-assistant canonical 合并；真实 tail assistant 不继承 anchor 元数据 |
| 独立 user-role 摘要紧邻真实 user | canonical `state.db` 有两行；provider payload 只在临时副本合并；数据库、sidecar、SSE 均没有聚合行 |
| 带 `api_content` 的真实 tail 与 prompt cache | API payload 包含“摘要 → 精确 sidecar 内容”；保留当前主循环已注入的 cache markers；不改变全局缓存顺序 |
| 重启恢复后请求模型 | provider payload 包含摘要和真实请求；数据库没有 provider-only 聚合行；恢复不会重新触发 tail 拼接 |
| `msg_limit` / `msg_before` / `turn_align` | 任一分页窗口不产生摘要 user 气泡，不隐藏真实 user |
| manifest / artifact 结算 | 摘要不进入普通 turn，不接收真实 user 的 artifact |

## 分阶段交付

1. Agent 先增加红测：覆盖两种原 `_merge_summary_into_tail` 边界、相邻 user 的 provider 副本，以及带 `api_content` 的缓存前合并；真实 tail 不被改写。
2. Agent 接入保留 role 的统一标记 helper，在无安全插入槽时降级为 user anchor，删除 tail 拼接分支；provider 合并仅复用既有临时整形接缝。
3. 完成 `state.db` 持久化和重启恢复测试。
4. WebUI 增加 `compaction_summary` 的 replay、分页和 manifest 回归测试。
5. 在隔离状态目录运行 Agent → WebUI 端到端压缩恢复验证。
6. 仅记录旧会话候选数量；未带权威标记的历史摘要不自动修改。

## 风险与回滚

最大风险是把真实 tail user 错标为 `context_anchor`，会导致其从展示和 turn 归属中消失。测试必须同时断言摘要被隐藏与真实 tail 保留。

该变更只增加持久化语义字段，回滚时可停止写入新 kind；已有带标记的新摘要仍会被旧 WebUI 当作普通行，因此发布顺序应先确保 WebUI 已能通用过滤 `context_anchor`。

为减少与上游主循环的冲突，本补丁不改动 `conversation_loop` 的 prompt-cache 顺序。
未来合并上游时，如上游已在消息整形后注入缓存标记，直接沿用上游行为，
不在 Fork 内维护第二套排序逻辑。
